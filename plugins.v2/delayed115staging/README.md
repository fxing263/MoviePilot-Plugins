# 115 延迟暂存（Delayed115Staging，1.3.3）

在 MoviePilot 整理完成与现有目录监控上传器之间，增加持久化延迟与硬链接暂存。
不连接 115，不实现上传、STRM、Emby 刷新、下载器或做种清理。

## 安装与配置

在插件市场添加 `https://github.com/fxing263/MoviePilot-Plugins`，搜索「115延迟暂存」安装或更新。

适用于提供 `app.sdk.events`、`app.sdk.logging`、`app.sdk.security` 的 MoviePilot；
插件基类支持新入口 `app.sdk.plugin.base` 和旧入口 `app.plugins`，
运行环境为 Linux/Docker。未适配不含这些 SDK 的旧版 MoviePilot。
将本目录作为完整的 `delayed115staging` 插件包导入插件安装目录；必须包含
`__init__.py`、`queue.py` 和 `dist/`。`frontend/` 是可选的前端构建源码。
安装前停用旧实例，不要用本插件目录替换其他插件。升级保留旧配置和任务，不自动启用。

配置界面采用 MP 标准 Vue 联邦插件组件，支持规则编辑、保存前验证、任务分页与操作。
可添加多组独立的“整理根目录 → 暂存根目录”，每组单独配置固定/大小延迟规则：

| 整理根目录 | 暂存根目录 | 规则示例 |
| --- | --- | --- |
| `/pt1` | `/115-staging1` | `/`：全部等待 60 分钟 |
| `/pt2` | `/115-staging2` | `/电影`：60 分钟，`/国产电视剧`：15 分钟 |
| `/pt3` | `/115-staging3` | `/动漫`：小于 5 GB 等 10 分钟，5 至小于 20 GB 等 30 分钟，20 GB 起等 60 分钟 |

- 整理根必须是整理后的库，不是下载/做种目录。每组的两个目录需要在同一文件系统。
- 整理根之间、暂存根之间、任意整理根与暂存根之间，均不得相同或互相包含。
- 每组规则目录相对于本组整理根。例如 `/pt2` 组下填写 `/电影`，实际匹配 `/pt2/电影`。
- `/` 表示整个整理根，不能与该组其他规则并存；子目录规则间重复、父子目录一律拒绝。
- 不同组可以各有 `/电影` 规则，因为 `/pt1/电影` 与 `/pt2/电影` 是不同的实际目录。
- 不处理未匹配文件。整理硬链接清理默认开启，空目录清理默认开启；暂存硬链接在确认成功后始终清理。

旧版单根配置在打开新版配置页时转换为一组映射，保留原有规则和清理开关，点击保存才写回。
已持久化任务继续使用创建时的根目录及到期时间，即使之后修改或移除了对应映射。

大小单位为十进制 GB（1 GB = 1,000,000,000 字节），各档左闭右开，
最后一档无上限；延迟允许 0 分钟。

每组源文件与对应暂存目录须在同一支持硬链接的文件系统中。不同组可位于不同磁盘。Docker 建议把共同父目录通过
同一个 bind mount 映射进容器；看似在同一磁盘的独立挂载仍可能返回 EXDEV。
不支持硬链接就保留原文件、标记失败，不回退到复制或软链接。
所有文件祖先路径拒绝符号链接，不允许 `..`。外部上传器不得修改硬链接内容：
写入任一硬链接会同时修改整理库和做种文件，应只读上传并按自身规则移除目录项。

## 路径与事件

订阅 `EventType.TransferComplete`，读取成功事件中 `transferinfo.target_item` 的本地存储标志，
以及 `file_list_new`（无列表时使用目标文件路径），根据实际路径选择唯一整理根映射。
不扫描下载目录，不回放安装前的历史库。

```text
/pt1/电影/示例 (2026)/示例.mkv
  ↓ 本组延迟到期
/115-staging1/电影/示例 (2026)/示例.mkv

/pt2/电影/示例 (2026)/示例.mkv
  ↓ 本组延迟到期
/115-staging2/电影/示例 (2026)/示例.mkv
```

使用 `os.link`，完整保留相对于本组整理根目录的分类、剧名、季及文件名；
不同整理根下同名的文件进入各自的暂存目录，不互相覆盖。任务页同时展示来源根与暂存路径。
不覆盖已有目标，即使目标同名。记录源文件设备号、inode、大小和纳秒修改时间，
到期时再次核对；等待期间变更的文件停止投递。同一路径存在活动任务时拒绝新版本抢占。

## 持久化与恢复

使用 `get_data_path()` 对应的插件独立数据目录，保存 `queue.json`，配合 `queue.lock` 文件锁。
写入采用临时文件、fsync、原子替换及目录 fsync；不需要宿主数据库迁移。
请持久化 MP 配置卷，不要删除插件数据目录。上次有效配置另存于 SDK PluginData 的
`accepted_config`；普通 UI 在提交前请求后端验证，绕过 UI 写入非法配置时实例停止并尝试恢复上次有效配置。

每个文件任务保存 ID、整理路径、完整相对路径、暂存路径、两个根目录、规则快照、延迟、
`created_at`/`ready_at`（Unix 秒）、源文件身份、尝试次数、错误、
清理选项、确认模式、链接成功时的目录身份、首次观察到删除的时间、上传确认依据及逐路径清理结果。

```text
waiting → linking → staged → confirmed → done
             ↓                    ↓
           failed           cleanup_failed
```

宿主定时服务每 15 秒检查，无 `sleep` 和自建后台线程。重启后读取原来的 `ready_at`，
不重新累计延迟；重复整理事件不创建重复任务。规则或根目录修改只影响新任务，旧任务保留快照。
整理文件清理必须同时获得任务创建时和当前配置的授权；中途关闭该选项会保留整理文件。
停用插件暂停登记、暂存和清理，不会取消外部已经开始的上传。
关闭期间的新整理事件不补扫；重新开启仅恢复已入队任务，延迟到期时间不重置。
整理路径直接删除后若收据尚未落盘即中断，重启将缺失文件记为 already_absent 并继续收尾。
硬链接创建与成功证据落盘之间中断可能需要人工核验，不能保证自动恢复上传确认。

`linking` 表示链接意图已先落盘。崩溃后若暂存路径仍是同一文件，恢复为 `staged`；
若文件不在，无法区分“尚未创建”和“上传器已经移走”，标记失败，必须核对上传器后手动重试，
不会盲目重复上传。损坏日志不会被空队列覆盖。失败重试仍遵守原到期时间。
取消只终止本插件任务，保留已存在文件，不能撤销外部监控器已经接收的上传。

## 上传确认与清理

提供两种确认方式，通用默认是手动确认：

- **手动确认 / 上传器成功回执**（`confirmation_mode: "manual"`）：在任务页核验远端文件后确认，
  或让现有上传器在核验远端成功后调用管理员确认接口。暂存文件消失不会自动触发清理。
- **上传器删除暂存文件后自动确认**（`confirmation_mode: "staging_deleted"`）：专用于用户已明确配置
  “115 上传成功后才删除上传源文件”的上传器。这里的上传源是本插件创建的**暂存硬链接**，不是做种源文件。
  不需要再逐个点击确认，也不需要对接上传器 API。

自动确认的条件：

1. 此任务以自动模式创建，且本插件成功创建暂存硬链接的证据已经持久化。
2. 两次检查相隔至少 30 秒，暂存文件均不存在；文件重新出现会重置观察时间。
3. 两次检查时，暂存根目录仍可访问且身份与创建时一致；文件或其下级父目录不存在均可确认，不读取整理文件身份。
4. 确认依据先落盘，再进入清理。确认记录为 `method=staging_deleted`、`confirmed=true`、
   `remote_verified=false`，明确是按上传器约定推定，不冒充已查询 115 的远端记录。

**此模式无法区分人工删除与上传器删除。不要手动清空暂存文件，也不要让其他程序按不同条件删除它们。**
暂存根目录消失、权限错误、目录替换会暂停确认并重置计时；暂存根目录正常时，
删除文件父目录或剧名目录也会进入两次缺失确认。观测到暂存文件被替换时，自动确认被阻断，可人工核验后处理。
插件不会为了检测删除重建丢失的暂存目录。同目录多个任务尚待确认时，暂不清理它们的空父目录。

确认模式在任务创建时快照保存；旧任务不会因切换模式被追溯判定成功。切回手动会暂停已有自动任务的
删除观测；重新开启后重新计时。崩溃导致缺少已落盘链接证据的任务同样需要人工核验。
插件停用时不推进任何任务。两种模式都不主动访问 115。

确认依据先落盘，定时服务再按清理开关处理：

1. 移除暂存硬链接；上传器已移走时记录 `already_absent`。
2. 按任务的整理根目录 + 相对路径直接 unlink 整理文件，不检查 inode、不隔离、不搜索其他硬链接。不读取或校验下载源路径；旧任务中的该字段忽略。
3. 仅向各自根目录以内逐层 `rmdir`，遇到非空目录停止，不删除根目录。

仅暂存文件清理先检查文件身份，再原子移入同目录下的任务专属 `.delayed115-cleanup-…/payload`，
复核后才 unlink。崩溃后继续处理隔离物；发现并发替换时尝试无覆盖恢复，原位置已有文件时
保留隔离物并报告准确路径，需人工检查。上传器应忽略 `.delayed115-cleanup-*` 目录。
任何异常均保留可追踪的失败状态；不删除 qBittorrent 源文件，也不调用下载器删除任务。

## 插件 REST 接口

全部接口要求 MoviePilot 管理员身份，接受宿主 Bearer / API 凭证认证，不提供匿名回调。
路径前缀是 `/api/v1/plugin/Delayed115Staging`；分身使用实际实例 ID。
返回 MP 标准 `{success, message, data}`。这些是可选插件的动态 REST 接口，未注册 MCP 工具。

| 方法与路径 | 请求 / 含义 |
| --- | --- |
| `POST /validate` | 完整配置对象；只校验，不写配置、不创建媒体目录 |
| `GET /tasks` | `data.tasks` 任务快照、`data.error` 实例错误、`data.enabled` 状态、`data.confirmation_mode` 当前模式 |
| `POST /task` | `{task_id, action: "retry"或"cancel"}` |
| `POST /task` | `{task_id, action: "confirm", verified: true, remote_reference: "115:file-id:…"}` |

手动/API 确认只接受 `staged` 任务，已确认/已完成的重复确认幂等。接口不接受调用方指定任意本地清理路径。
调用方必须把任务 ID 与该暂存文件的远端结果准确关联，不能仅凭同名文件确认。

示例配置：

```json
{
  "enabled": true,
  "confirmation_mode": "staging_deleted",
  "cleanup_organized": true,
  "cleanup_empty_dirs": true,
  "mappings": [
    {
      "library_root": "/pt1",
      "staging_root": "/115-staging1",
      "rules": [{"directory": "/", "delay_minutes": 60}]
    },
    {
      "library_root": "/pt2",
      "staging_root": "/115-staging2",
      "rules": [
        {"directory": "/电影", "delay_minutes": 60},
        {"directory": "/国产电视剧", "delay_minutes": 15},
        {"directory": "/动漫", "tiers": [
          {"below_gb": 5, "delay_minutes": 10},
          {"below_gb": 20, "delay_minutes": 30},
          {"below_gb": null, "delay_minutes": 60}
        ]}
      ]
    }
  ]
}
```

## 一次全量硬链接与历史清理（1.3.0）

勾选 `scan_once` 并保存，启用插件后由下一次队列调度扫描所有映射根目录，
仅登记匹配规则的普通文件，包含字幕/刮削文件；跳过符号链接及内部隔离目录。
新任务延迟为零，已有任务保持原状态和延迟，不会重复创建或自动重试失败任务。
成功扫描后持久化关闭开关；中断或错误时保持开启，后续重扫去重。
扫描期间不开启上传接口，仍通过原暂存监控上传；目录必须全部可读。
仅配置整理目录，不能将下载/做种目录配置为整理根目录。

`history_days` 默认 7 天，范围 1–3650。启用时每天一次删除超过保留期的 done 记录，
按完成时间计算；旧记录缺少完成时间时从首次维护起保留。失败、取消和未完成任务不删除。
历史清理不操作任何媒体文件。若关闭整理清理，记录过期后再全量扫描会重新投递仍存在的文件。
