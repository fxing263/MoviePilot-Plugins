# 媒体整理增强（Rapid115Upload 1.2.2）

MP 正常整理成功后，将**整理后的本地目标文件**按插件映射入队，在后台上传115。
失败事件、非本地目标和映射范围外文件不入队。原本的重命名、硬链接和已整理标签流程不变。

## 配置与使用

- 在 MP 存储设置中授权115；插件复用宿主授权，不另存凭据。
- 从 MP“设置 → 目录管理”选择本地媒体库（整理目标）目录，再填写对应115目标根目录，保留相对目录和文件名。
  不再手填本地根目录。下载目录和远端媒体库不会作为选项；相同目标路径只显示一次。
  保存时后端核对系统目录；系统目录移除或改名后，旧映射停止接收新整理事件，已有队列保留。
  例如 `/pt1/links → /影视库`，整理后的 `/pt1/links/电影/X/X.mkv` 上传至 `/影视库/电影/X/X.mkv`。
- 每组目录映射独立配置最大秒传尝试次数（默认 **3**），并设置延迟分钟数组（默认60、360、1440）。
  旧配置中未设置目录次数的映射继承原全局值，保存后不再使用全局次数；新增映射默认3次。
  只有明确未命中才消耗秒传次数；达到次数后立即普通上传。授权、网络错误不会提前触发普通上传。
- 每组映射可设置“首次上传前等待（第0次）”，单位分钟，默认0立即尝试。入队时保存首次到期时间，等待不占并发、不消耗尝试次数；重复事件和重启不重新计时，修改配置仅影响新任务。
- 同时处理数默认 **2**，范围1–16。秒传和普通上传共享额度，延迟重试不占用工作线程。
- 已移除仅入队测试模式，启用插件后按正常流程处理队列；旧配置中的 `test_mode` 不再生效。
- 可启用“下载器监控增强”：从 MP 已启用的 qB 下载器中多选，默认白名单 `未整理`，黑名单 `已整理`、`BDMV`。
  留空下载器表示全部已启用的 qB；选定后未选 qB 不参与待整理查询，但普通列表、Hash查询及非qB模块仍沿用宿主规则。黑名单优先，标签在 qB 查询端下推。
  不要求 `MOVIEPILOT` 标签，普通下载列表、普通 Hash 查询不变；保留1.1.1的整种子完成检查。
- 合并监控和独立 `QbittorrentTagMonitor` 不得同时启用。检测到挂钩占用时合并版保持关闭并提示，
  不擅自停用、修改独立插件配置。停用独立插件后再启用合并监控。
- 本版不启动自定义目录监控。旧 `watch_mappings` 仅保留兼容数据，不启动观察器或补扫。

## 标签与整种子关联

整理事件持久保存下载器名称、Hash、源文件、目标文件、整理记录 ID 的关联。
插件额外持久保存本地整理失败事件携带的下载来源，手动重整完成事件缺少关联时，按源文件绝对路径和文件身份恢复唯一的下载器/Hash。
失败事件只记录关联，不创建上传任务；成功事件不新增来源缓存，保留失败关联直到确认种子已添加“已上传”标签后，再删除对应的唯一失败缓存，上传任务自身仍保留种子关联；重启/升级后关联保留。不扫描qB全量种子，不修改MP本体。
同路径文件被替换、来源对应多个种子或插件从未接收过原关联时不猜测，仍可上传但不能自动回写标签。
MP 确认种子已整理后，合并监控移除 `未整理`。
上传完成后按明确 Hash 读取 qB 文件清单，使用宿主下载器路径映射核对：
**所有选中下载的主媒体文件都已完整下载、整理入队并上传，且已确认 `已整理`，才添加 `已上传`。**

主媒体扩展名复用 MP 的 `RMT_MEDIAEXT`，不区分扩展名大小写。字幕、NFO、图片等附件不作为标签完成条件，已有附件队列失败也不阻挡主媒体标签。
主媒体文件未整理、位于映射范围外、上传失败或取消时不添加标签；未选下载的文件（priority=0）不计入。
仅有附件、没有选中主媒体的种子不会被标记。此规则不额外上传或删除附件。
没有下载器或 Hash 的手动整理仍可上传，但不回写种子标签。
旧版本未保存种子关联的历史任务不能凭路径猜测回写标签。

标签回写失败每60秒重试并显示原因，文件的成功状态不回滚，也不重复上传文件。
相同 Hash 在不同下载器中独立处理。每次仅查询关联种子，不枚举全部种子。

## 页面与数据

- “媒体整理”保留本地整理记录：未配置对应115映射且无关联上传任务时，不显示115行；匹配映射但尚未入队时显示“未入队”。
  有关联任务时展示115目标路径、状态、错误和下次尝试，即使后来删除映射也保留历史状态。
  普通上传展示“普通上传”；秒传不额外显示方式标签。
- 配置使用“基本设置、目录映射、qB标签、BDMV上传”四个分页；多组映射通过下拉切换，底部保存按钮固定。分页切换保留未保存内容。
- 插件管理弹窗仅用于配置，不重复显示记录，也不启动队列查询和轮询。
- 侧边栏“115秒传”展示上传队列、统计、大小、状态和任务操作，以及标签回写未完成原因。
- 上传队列增加进度/速度列：计算哈希、秒传检查、提交校验显示阶段进度；普通上传使用OSS实际字节回调显示百分比和每任务速率。
  进度只保存在内存，失败/完成后清除；回调停滞5秒速率归零。前台有运行任务时每3秒刷新，空闲每15秒刷新，页面隐藏时暂停轮询。
- 插件ID保持 `Rapid115Upload`，兼容现有 API、侧栏和队列目录。
- `queue.json` 使用文件锁、原子替换与 fsync。旧任务默认最多3次明确未命中后普通上传；
  已登记的新任务保留入队时的路径、间隔和次数，修改配置只影响新任务，并发数立即随重载应用。
- 重启取得消费者锁后才恢复中断任务，工作线程不会相互领取正在执行的任务。
  同名远端文件必须大小、SHA1完全一致才能确认成功；不覆盖冲突文件。
- 普通上传复用项目已有 oss2 依赖和115开放接口协议，读取同一个已校验文件句柄，分片间响应停止。
  提交后核对远端路径、大小和SHA1。失败时尽力回收未完成分片；网络中断导致回收失败时可能残留OSS分片。
  凭据失效或普通上传中断会延迟后重新尝试，不保证跨进程续传分片。
- 停用等待在途请求退出；运行中任务不能手动取消，等待/暂停任务可取消或重新排队。
- “上传完成后处理”默认保留硬链接文件；选择删除后，秒传或普通上传确认成功并保存状态后，删除整理后的本地目标文件，不操作下载源路径。
  第三个选项“删除硬链接文件及空的父文件夹”会继续向上移除空目录，遇到非空或不可删除目录即停止，始终保留当前映射的整理根目录；没有有效映射时不清理父目录。
  按用户约定，映射目录只存放硬链接；删除不额外校验硬链接来源或文件身份，不保存删除结果。删除失败仅输出运行日志，不回滚成功状态或重新上传。
  此设置重载后作用于后续完成的任务，不追溯删除历史成功文件。队列损坏保留原件，不自动重建。
- JSON全量快照适合普通规模队列；历史记录不自动裁剪。更换115账号前应停用并处理旧队列，任务尚未绑定账号身份。

## 安装产物

安装完整插件目录（Python 文件、`dist/`、`native-dist/`）；无需替换宿主前端。运行配置不会随源码同步改变，重载后使用新版插件。

## 媒体整理记录

整理分组新增“媒体整理记录”入口，读取 MP 原有整理历史与插件上传队列，不复制历史数据。完整移植原版 TransferHistoryView、重新整理、媒体选择、删除、恢复和队列弹窗及其依赖，来源指纹见 `native/source-manifest.json`，构建方式见 `native/README.md`。

成功及失败记录均保留原版重新整理菜单；支持原版批量选择、分组、删除与恢复操作，操作权限由 MP 校验。重新整理保留目的存储、路径、方式、识别来源、媒体选择、预览与后台提交等原版选项。两个入口共享同一套历史与整理接口；后台受理不代表整理成功。

115 行继续显示目标路径对应的上传状态，无映射且无任务时隐藏。普通上传显示方式、进度与速度。重新整理成功后仍由原插件事件流程判断目标映射、入队及种子标签，不新增独立整理流程。

原版页面在插件内独立挂载，适配宿主 API、用户权限、主题及内存路由；不修改 MP 后端和宿主前端源码。宿主需支持多入口插件侧栏、AppPageHistory 联邦协议及移植页面调用的现有接口。

## 预览修改整理后的路径

仅本插件新增“媒体整理记录”入口的历史重新整理弹窗支持：先点预览，再逐项修改“整理后”的完整路径（目录和文件名），可恢复默认。修改表单条件或重新选择记录后需重新预览。没有修改路径时仍调用 MP 原手动整理接口。

修改后的目标必须位于系统目录管理的本地媒体库目录内，不能与源文件相同、越界或与本批次其他目标冲突。增强提交先重新只读规划并校验，再将完整目标计划随 MP 整理任务同一事务保存；后台执行、历史更新与整理完成事件仍由 MP 处理。115 上传依据实际整理成功的目标路径匹配映射。

增强接口为管理员操作，不修改宿主原页面。它依赖当前 MP 的持久整理计划能力；不兼容宿主应拒绝增强请求，不可静默忽略自定义路径。


## BDMV 整目录上传（CD2）

默认关闭。在“BDMV 上传”分页选择已有 qB 下载器、五段 Cron 扫描周期（默认 `0 2 * * *`，MP 时区），并配置独立路径映射。该分支不经过普通媒体整理，也不受普通整理的 BDMV 黑名单影响。

连接复用已安装并运行的 **CloudDrive2储存（CloudDriveDisk）** 插件，不另外保存 CD2 账号。CD2 需预先添加本地存储，能访问下载文件。每组映射包含：

| 配置 | 示例 |
| --- | --- |
| MP 可见下载根（应用下载器路径转换后） | `/downloads` |
| CD2 文件列表中的本地源根 | `/本地存储/downloads` |
| CD2 文件列表中的 115 目标根 | `/115/原盘` |

例如 `/downloads/电影A` 上传到 `/115/原盘/电影A`，保留整个文件夹结构。父目录不存在时创建；同名目标已存在时停止，避免覆盖。

定时扫描只拉取 BDMV 标签种子，并要求同时有“未整理”、没有“已上传”，整种子所有文件完整下载且处于独立目录。CD2 源清单必须与种子清单一致，避免上传相邻种子或不完整目录。此流程包含目录中的字幕、NFO 等种子文件，始终保留本地文件做种。

`bdmv.json` 独立持久化提交意图和任务关联。每分钟查询 CD2 复制状态；接受请求不代表上传完成，任务消失或结果不明确时不盲目再次提交、不写标签。确认完成后先添加并读取确认“已上传”，再删除并读取确认“未整理”，保留 BDMV 标签。标签失败只重试标签，不重传目录。侧栏上传队列下方展示 BDMV 任务及进度。

停用插件暂停新的扫描与核对，已经提交给 CD2 的复制继续由 CD2 执行。重启、升级后恢复核对已有任务。部署时仍需用实际 CD2 服务验证目录复制、任务保留及 115 提供商元数据兼容性；离线测试不替代真实上传验证。

BDMV 完成判定仅使用关联 CD2 复制任务：明确 Completed、上传文件数等于总数且与种子文件数一致、失败/跳过/取消为零。上传后不再读取115目标文件夹。进度来自 CD2 的总字节数/已上传字节数和文件计数，每分钟更新；任务记录缺失仍不视为成功。上传前仍检查源清单、创建目标父目录并检查同名冲突。

BDMV 扫描周期使用 `分 时 日 月 周`，五段之间用空格分隔，例如 `*/30 * * * *` 每30分钟、`0 2 * * *` 每天02:00、`0 2 * * mon` 每周一02:00。沿用 MP 的 APScheduler Cron 语义，星期建议使用 mon–sun（数字0为周一）。旧版 `time: HH:MM` 自动转换为等价 Cron，已有扫描时间不变。进度核对仍每分钟一次，不随扫描周期改变。
